# Mock strategy (MSW)

## Switch

```bash
# apps/frontend/my-app/.env.local
NEXT_PUBLIC_API_MOCKING=enabled   # MSW answers in the browser
NEXT_PUBLIC_API_URL=/api
RESCOM_API_URL=http://localhost:4000
```

`disabled` (or unset) sends every request to the real backend. `NEXT_PUBLIC_*` values are
inlined at build time: restart `next dev` / rebuild after changing them. With mocking
disabled the MSW code is dead-code-eliminated from the bundle.

## Boot

`components/providers/MswProvider.tsx` (in `app/layout.tsx`) dynamically imports
`mocks/browser.ts` and starts the worker (`public/mockServiceWorker.js`, generated by
`npx msw init public --save` — regenerate after upgrading `msw`). The app renders nothing
until the worker is active so no request races past it. Unhandled requests are bypassed
to the network, so screens not yet migrated keep working.

## Layout

```
mocks/
├── browser.ts          setupWorker(...handlers)
├── envelope.ts         ok() / fail() — exact backend envelope
├── scenarios.ts        runtime scenario switch + latency
├── handlers/
│   ├── index.ts        all handlers
│   ├── auth.ts         /auth/login, /auth/register, /auth/me, /auth/csrf, /auth/refresh, MOCK-ONLY routes
│   └── demographics.ts GET /demographics
└── data/auth.ts        demo accounts, id/name mappers
```

Handlers validate bodies with the same `@rescom/schemas` the backend uses and return the
backend's error codes. Auth state is delegated to the legacy `mockRepository`
(`lib/mock`) so pages that still read it see the same signed-in user. Legacy ids like
`user-active-002` are mapped to stable UUIDs because the shared schemas require UUIDs.

## Reset

`?msw-reset=1` (or `resetMockDb()` in `mocks/db/store.ts`) clears every mock key in
localStorage: the `rescom:mockdb:*` collections, the legacy demo store
`rescom_demo_v1_store` (signed-in user, surveys…), passwords registered through MSW
(`rescom:msw-credentials`) and the remembered scenario (`rescom:msw-scenario`).

## Scenarios

Open any page with `?msw=<scenario>`; it is remembered (localStorage) until `?msw=default`.
Default latency is 400–700 ms.

| Scenario | Effect |
|---|---|
| `slow` | 2.5 s latency |
| `invalid-credentials` | login → 401 |
| `locked` | login → 403 `AUTH_USER_LOCKED` |
| `validation` | login/register → 400 with zod details |
| `email-taken` | register → 409 |
| `rate-limited` | login/register → 429, `Retry-After: 45` |
| `server-error` | login/register → 500 |
| `network-error` | login/register → network failure |
| `profile-incomplete` | `/demographics` → `isComplete: false` |
| `unauthenticated` | Every session route (`/auth/me`, `/auth/refresh`, data endpoints) → 401; guest routes (login, register, Google, `/auth/password/forgot`) behave normally |
| `api-error` / `api-offline` | Data endpoints → 500 / network failure (not login/register/me/refresh/Google) |
| `google-link-required` | Mock "Tiếp tục với Google" → 409 `AUTH_GOOGLE_LINK_REQUIRED` → `/auth/link-google` (15d, email `minh.le@fpt.edu.vn`) |

## Adding a handler

1. Implement the service in `lib/<domain>` against the real (or ASSUMED) contract.
2. Add `mocks/handlers/<domain>.ts` using `apiUrl()` paths, `ok()`/`fail()`, and
   `applyScenario()` if the screen needs error/latency states.
3. Register it in `mocks/handlers/index.ts`. Keep mock data in `mocks/data/`.
