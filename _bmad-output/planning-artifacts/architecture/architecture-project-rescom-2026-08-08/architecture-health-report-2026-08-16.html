Executive verdict

The technology direction is viable; the architecture has not converged.

A NestJS modular monolith, PostgreSQL source of truth, immutable Form Versions, transactional outbox, internal-only Research Integrity Engine, progressive policy enforcement, and optional AI are defensible. The blocking failure is that the canonical SPEC/spine, an unratified “Architecture V2,” and the current Prisma schema describe materially different systems.

Pause at the schema and migration boundary. Do not generate a first migration until authority, identity/versioning, ledger, integrity lineage, outbox, and privacy contracts are reconciled.

Unratified conflict

Two Architecture V2 copies

Byte-identical proposals exist at the repository root and in planning artifacts. They change external assessment behavior, replace FraudLog, and change worker deployment. Parts of the current Prisma schema already reflect those incompatible choices.

Disposition: extract compatible material, reconcile it through an architecture Update, then archive one historical copy.

Critical issues

C-01

Split-brain architecture authority

Canonical rules say External responses are NOT_ASSESSED, FraudLog remains a separate security record, and background processing is in-process. Architecture V2 specifies reduced-confidence External assessments, replaces FraudLog, and deploys a separate worker.

Required: declare the canonical contract, reconcile V2, and block migration generation until completed.

C-02

The financial schema is not double-entry

The current LedgerTransaction has one user, one balance type, and one signed amount. It cannot prove balanced movement, conservation, escrow ownership, or atomic transfer semantics.

Required: replace it with an immutable journal header and at least two balanced entries posted to explicit accounts.

C-03

Form/version/attempt/response identity is not enforceable

There is no explicit immutable FormVersion, version references are nullable scalars without foreign keys, guest Internal responses cannot be represented, and duplicated form/respondent references can disagree with the linked attempt.

Required: make Attempt the submission context, reference one immutable FormVersion, and model authenticated/guest identity intentionally.

C-04

The integrity pipeline cannot meet its canonical contract

Consent, event deduplication, raw-event lineage, replayable signals, assessment applicability/coverage/revision, immutable reliability and survey-quality snapshots, trust projection, and robust outbox semantics are missing or under-specified.

Required: redesign this schema slice directly from canonical CAP-1 through CAP-7 before the first migration.

C-05

Privacy and governance gates block production telemetry

Consent, retention/deletion, access audit, policy promotion, review/appeal ownership, and Survey Quality evidence thresholds remain unresolved while behavioral telemetry and raw identifiers are already modeled.

Required: collect no production telemetry until these controls are approved, testable, and represented in schema and stories.

High-risk findings

H-01 · H-02

Backend, workspace, migrations, and runtime are targets only

No NestJS source, root workspace, shared packages, migration history, or running database evidence exists. Prisma syntax validation is not runtime proof.

H-03 · H-04

Worker and package baselines conflict

Worker topology is contradictory. Prisma CLI/client are v6 while config is v7; Node 18 documentation conflicts with current Prisma/Nest requirements and there is no pinned repository toolchain.

H-05 · H-06

Security/session and user capability contracts are incomplete

Cookie JWTs have no binding CSRF, key rotation, session-version, expiry, audit, or origin posture. One mutually exclusive role cannot express the documented dual Publisher/Respondent capability without an inheritance rule.

H-07 · H-08

Telemetry ownership and append-only guarantees are weak

IntegrityEvent mixes economy/policy/review events into a cross-domain bus. Append-only behavior exists only in prose, not database permissions, triggers, repository restrictions, or tests.

H-09 · H-10

Some structural mandates are over-engineered

Strict four-layer Clean Architecture for every small feature, mandatory Turborepo, and unconditional Day-1 Redis add ceremony without current value. Preserve seams and ownership where risk justifies them.

H-11

Production operations are unproven

No backend container, CI/CD, health endpoint, observability, backup/restore test, RPO/RTO, secrets implementation, load test, or deployment topology is present.

External Form flow: completion code + time barrier + dispute controls → applicability NOT_ASSESSED → economy settlement. It does not feed full Response Integrity, Reliability, or Survey Quality assessment.

Minimum durable model corrections

  1. Explicit Survey/Form aggregate and immutable FormVersion.
  2. SurveyAttempt pins one version and intentionally represents authenticated or guest participation.
  3. Response references Attempt; duplicated identity/version fields are removed or constrained.
  4. Versioned IntegrityConsent with scope, timestamps, and lifecycle semantics.
  5. Events add client ID, server receipt time, schema version, consent reference, payload validation, and dedupe key.
  6. Durable signal/feature snapshots preserve derivation version and source lineage.
  7. Assessments add applicability, coverage, immutable policy relation, revision, reason codes, and unique lineage.
  8. Append-only Respondent Reliability and Survey Quality snapshots.
  9. Integrity findings/reviews remain separate from security FraudLog.
  10. Trust edges are typed, rebuildable projections, never authoritative state.
  11. LedgerJournal plus balanced immutable LedgerEntry rows and an idempotent command reference.
  12. Outbox adds unique idempotency, aggregate version, lease, retry/backoff, terminal state, and handler deduplication.
