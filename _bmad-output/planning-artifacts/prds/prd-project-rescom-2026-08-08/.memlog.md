- (decision) Source inputs: Overview doc (non-tech), SRS v1.0 (Draft), Architecture doc (rescom.md). Scope change: Form Builder + AI Form Generator moved from Phase 2 to GO LIVE per architecture doc.
- (decision) Stakes: Launch/Production. Mode: Coaching path. Product is a two-sided academic survey exchange marketplace for students, piloting at FPT University Da Nang.
- (decision) GO LIVE scope = SRS MVP + Internal Form Builder + AI Form Generator. SRS needs update to reflect this scope change. Entry point: Journey-led coaching path.
- (decision) Vision: RESCOM exists solely to replace social media survey posting with quality-targeted distribution. Core value props: (1) surveys reach the right audience, (2) respondents receive token rewards for internal exchange. RESCOM is NOT a money-making app — points are internal tokens, not currency.
- (decision) User acquisition: social media ads. Onboarding: mandatory demographic+interest form before anything else.
- (decision) Publisher has dual form options: 3rd-party (Google Forms) or Internal Form Builder. Internal Form Builder costs LESS tokens — incentivizing platform-native forms. NEW: Dashboard must show response data for internal forms, traffic analytics (by hour, day, week, month), click-through tracking. When sample quota is met, auto-hide from marketplace. Publisher can reopen survey later by paying more tokens for a larger sample size.
- (assumption) OPEN: What happens when Publisher doesn't have enough points to post? User hasn't decided yet. This is a UX gap that needs resolution before launch — cold-start problem.
- (decision) Respondent lands on Marketplace first. External form: system auto-generates unique 6-digit code on server (NOT manually set by Publisher). Publisher must paste this code at end of their Google Form. Respondent enters code in modal to claim reward. If Publisher forgot code, Respondent can report to Admin.
- (decision) Internal form: system fully monitors — no completion code needed. Auto-pays points. Validation includes: (1) cross-reference respondent answers with onboarding demographic data for consistency, (2) time-based validation to detect bot behavior. Points credited immediately or within 1-2 minutes.
- (decision) NEW feature: Gamification — streak system + leaderboard. Leaderboard ranks: (1) most surveys completed, (2) longest streak. This drives Respondent retention.
- (decision) Pending period split: Internal forms = instant payout (system auto-validates via demographic cross-check + bot detection). External Google Forms = keep 48h pending for Publisher manual review. This is a change from SRS which had 48h for everything.
- (decision) Admin dashboard: active user list, ban/unban accounts, transaction dashboard. Complaints: Admin reviews evidence (screenshots) uploaded by complainant, then sends email to BOTH parties (complainant + accused). NEW admin powers beyond SRS: (1) ban/unban users, (2) approve surveys BEFORE marketplace listing (moderation gate), (3) edit user info in system.
- (event) Discovery complete. All 3 journeys captured (Publisher/Respondent/Admin). 10 changes vs SRS identified. 5 concerns noted. Beginning PRD draft.
- (decision) Cold-start resolution: No free publishes. Publishers must complete other surveys to earn enough points if their starter points are insufficient.
- (decision) Internal Form discount: 20% compared to external forms. Moderation SLA: Admin approves whenever free (no strict SLA). Auto-ban: System only warns/flags users; banning is strictly manual by Admin.
